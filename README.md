# Салон красоты «Стиль & Красота»

Веб-приложение салона: публичная страница с услугами и онлайн-записью, а также административная панель для просмотра заявок и управления каталогом. Проект предназначен для демонстрации и учебной работы.

## Возможности

- Адаптивный лендинг: услуги, команда, запись и контакты.
- Форма записи с выбором мастера, услуги, даты и свободного времени.
- Админ-панель по адресу `/admin`: список записей, статусы, фильтрация, услуги и расписания.
- Локальный API сохраняет услуги и записи в SQLite.
- Начальные услуги, мастера и демонстрационные записи добавляются автоматически, если соответствующие таблицы пусты.

## Технологии

- **Клиент:** React 19, React Router DOM 7, Tailwind CSS, Create React App.
- **Сервер:** Node.js, Express, Sequelize, SQLite (`sqlite3`).
- **Обмен данными:** JSON API; в разработке запросы `/api` проксируются на `http://localhost:5001`.

## Запуск локально

Нужны Node.js и npm. Команды выполняйте из корня репозитория — папки, где находится этот README и корневой `package.json`.

### 1. Установить зависимости

```sh
npm install
npm install --prefix server
```

### 2. Настроить сервер при первом запуске

Создайте локальный файл окружения:

```sh
cp server/.env.example server/.env
```

`server/.env` не хранится в Git. Основные настройки:

| Переменная       | Значение по умолчанию | Назначение                                 |
| ---------------- | --------------------- | ------------------------------------------ |
| `PORT`           | `5001`                | Порт API                                   |
| `ADMIN_LOGIN`    | `admin`               | Логин админ-панели                         |
| `ADMIN_PASSWORD` | `admin123`            | Пароль админ-панели                        |
| `DB_PATH`        | `./database.sqlite`   | Путь к файлу SQLite относительно `server/` |

### 3. Запустить сервер и клиент

Откройте два терминала в корне проекта.

В первом запустите API:

```sh
npm run server
```

Во втором запустите React-приложение:

```sh
npm start
```

Откройте `http://localhost:3000`. Панель администратора доступна по адресу `http://localhost:3000/admin`. Для входа по умолчанию используйте `admin` / `admin123` (если значения не переопределены в `server/.env`).

Если порт `5001` уже занят, остановите ранее запущенный сервер в его терминале (`Ctrl+C`), затем запустите `npm run server` снова.

Для разработки с автоматическим перезапуском API используйте `npm run dev:server` вместо `npm run server`.

## API

Основные маршруты:

| Метод             | Путь                                     | Назначение                                 |
| ----------------- | ---------------------------------------- | ------------------------------------------ |
| `GET`             | `/api/services`                          | Список услуг                               |
| `GET`             | `/api/masters`                           | Список мастеров                            |
| `GET`             | `/api/masters/:id/slots?date=YYYY-MM-DD` | Свободное время мастера                    |
| `POST`            | `/api/appointments`                      | Создать запись                             |
| `POST`            | `/api/auth/login`                        | Получить токен администратора              |
| `GET`             | `/api/admin/appointments`                | Получить записи (Bearer-токен)             |
| `PATCH`           | `/api/admin/appointments/:id`            | Изменить статус или заметку                |
| `POST`            | `/api/admin/services`                    | Добавить услугу (Bearer-токен)             |
| `PATCH`, `DELETE` | `/api/admin/services/:id`                | Изменить или удалить услугу (Bearer-токен) |

Защищённые маршруты требуют заголовок `Authorization: Bearer <token>`. Ошибки возвращаются в JSON с полем `error`. Полный перечень маршрутов и примеры запуска сервера находятся в [server/README.md](./server/README.md).

## Данные и ограничения демо

- База создаётся автоматически в `server/database.sqlite`; локальная БД и `.env` исключены из Git.
- Услуги и записи формы бронирования хранятся через API в SQLite. Услуги можно редактировать из админ-панели.
- Расписание мастеров для демо сохраняется в `localStorage` браузера.
- Старые заявки из прежней версии приложения, сохранённые только в `localStorage`, автоматически в SQLite не переносятся.
- Токен администратора хранится в памяти сервера и сбрасывается при перезапуске.
- Это учебный демо-сервер, не предназначенный для реальных персональных данных или production-эксплуатации. Для публикации нужно отдельно разместить API и настроить безопасную аутентификацию.

## Полезные команды

```sh
npm start                 # запустить клиент
npm run server            # запустить API
npm run dev:server        # запуск API с перезапуском при изменениях
npm run build             # production-сборка клиента
npm test -- --watchAll=false
```

GitHub Pages публикует только статический клиент — локальный Express/SQLite API туда не входит. Для работы записи и админ-панели на опубликованном сайте API нужно разместить отдельно и настроить адрес запросов.
